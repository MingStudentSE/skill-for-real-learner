# 渐进式访谈指南

## 原则

把访谈当作“发现会改变 Agent 行为的证据”，而不是收集完整个人资料。一次只问 1 至 3 个高杠杆问题；每轮先复述已知，再指出为什么下一个问题重要。

## 三种深度

### 快速版

适合用户说“先建起来”“不要问太多”。最多补齐：

1. Agent 主要帮助什么。
2. 用户最在乎的一种合作方式。
3. Agent 最不能变成什么。

随后生成最小可用草稿，并把未确认部分省略。

### 标准版

分两轮完成。

第一轮聚焦用户：

- 希望如何称呼，主要使用什么语言？
- 先要结论还是先看推理？
- 哪种 Agent 行为最浪费时间或最让人反感？

第二轮聚焦 Agent：

- 它主要是执行者、研究伙伴、教练、反方还是其他角色？
- 低风险时主动推进，还是默认先确认？
- 用户判断可能错误时，它应多直接地指出？

### 深入版

只在用户希望形成鲜明且稳定的长期协作关系时使用。围绕真实样本追问：

- 给一个“这回答很对味”的例子，具体好在哪里？
- 给一个“看了就皱眉”的例子，具体错在哪里？
- 时间、质量、可逆性冲突时如何排序？
- 情绪高压时需要安抚、澄清、挑战还是先执行最小动作？
- 哪些外部行动必须停下来确认？
- 哪些事实改变后必须更新 `USER.md`？

## 优先使用对比题

把抽象形容词转成行为选择：

| 弱问题 | 更好的问题 |
| --- | --- |
| 想要什么性格？ | 更直接还是更委婉？出现错误时能否明确反驳？ |
| 喜欢什么回答？ | 先给结论再给依据，还是边推理边展开？ |
| 要不要主动？ | 可逆的低风险动作可直接做吗？写入和外发分别如何处理？ |
| 技术水平如何？ | 哪些概念可以直接用，哪些需要先定义？ |

## 从材料中提取

有现成聊天、笔记、提示词或旧文件时：

1. 先读完整相关材料，不只搜关键词。
2. 提取重复出现的偏好、纠正、边界和满意/不满意样本。
3. 区分一次性要求与稳定模式。
4. 用一段不超过五条的摘要向用户讲回。
5. 只确认会影响最终文件的推断。

## 停止线

满足以下条件即可停止访谈并起草：

- 能一句话说明用户如何被更有效地帮助。
- 能一句话说明 Agent 的中心角色。
- 至少有两条在压力下可预测行为的原则。
- 已知最关键的写入或外部行动确认边界。
- 没有把敏感推断当成事实。

不要为了完整感继续采集无关资料。
