# 生成学习 SOP

将已经达成共识的学习讨论，整理为一个学习使命下稳定阶段的行动规程。

只在学习使命和当前决策已澄清时编写 SOP；不要自行开启战略质询。

## 读取学习状态

阅读当前对话，以及已有的 `STRATEGY-MAP.md`、已关闭的 `strategy-decisions/`、`MISSION.md`、`CONTEXT.md`、`RESOURCES.md`、`LEARNING-SOP.md` 和相关 `learning-records/`。其中的术语与已展示的基础就是起点，不要让学习者重复它们。

现实目标的变化属于学习使命变化，不能静默修改。替换 `MISSION.md` 前先与学习者确认。

## 创建使命指南针

如果缺少 `MISSION.md`，按现有 `teach` skill 的格式创建。它只记录学习者的现实原因、可观察的成功标准、约束与当前不在范围内的事项。学习使命比一个学习阶段更广、更持久；它必须服务 `STRATEGY-MAP.md` 中已经确认的总体战略，不能静默重写总体战略。

## 编写学习 SOP

先阅读 [`LEARNING-SOP.md` 格式](references/sop-format.md)，再创建或更新 `LEARNING-SOP.md`，将以下决策具体化：

1. **起点**：区分已经展示的能力、学习者自述的熟悉度和仍未回答的不确定项。
2. **核心问题与最小必要知识**：用一句源于现实差距的具体问题界定本阶段；再列出解决它所需的最小概念、模型、案例或前置技能。它们是范围边界，不是课程目录，也不是掌握证明。
3. **目标能力**：写出语境中的可观察行动，而不是待覆盖主题。“为这个服务解释依赖关系图”是能力；“依赖关系图”只是主题。
4. **学习方法**：选择适合学习者约束与领域的可持续、低阻力节奏和反馈循环。课程要形成长期记忆，而不只是制造熟悉感。
5. **资源策略**：指向本阶段需要的可信资源，并暴露重要缺口；让资源服务核心问题和最小必要知识，不要编造权威来源。
6. **复盘检查点**：明确何时进行学习复盘以及需要哪些证据。检查点跟随有意义的能力簇、真实任务或一段练习，而不是固定课时数。

真实未知项应保持可见，而不是当作事实处理。SOP 只描述阶段层面的稳定方法与可观察结果，不写成日程表。

## 输出

交付或更新 `MISSION.md` 与 `LEARNING-SOP.md`，并概述当前阶段、目标能力、第一个复盘检查点与未解决假设。后续流程只以这些工件为输入；本 skill 不在此处启动任务规划或教学。

完成条件：`MISSION.md` 准确，且 `LEARNING-SOP.md` 足以让后续教学在不重做规划对话的情况下选出下一项有价值的任务。
