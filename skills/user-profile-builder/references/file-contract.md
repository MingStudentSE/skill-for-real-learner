# 文件契约

## 内容归属

| 文件 | 保存的内容 |
| --- | --- |
| `USER.md` | 称呼、语言、必要时区、稳定背景，以及会影响协作的输出与确认偏好 |
| `SOUL.md` | 单一中心角色与使命、通常 3–7 条判断原则、语气，以及该角色必要的边界 |
| `IDENTITY.md` | Agent 名称、简短角色、图标等识别信息 |
| `AGENTS.md` | 工作区启动、操作、验证与写入规则 |
| `TOOLS.md` | 工具路径、命令与运行事实 |
| 项目状态或按需记忆 | 临时进度、历史证据、决策经过与特定项目细节 |

同一含义只保留一个权威位置。用户的表达偏好归 `USER.md`；`SOUL.md` 保留换一个用户后仍成立的角色原则。已有工作区规则足以表达的内容用必要的指针连接，避免复制整段规则。

`SOUL.md` 的原则描述遇到不确定、分歧或风险时如何取舍；语气服从任务。证据不足时使用更少原则并说明待确认处，数量不构成补写依据。它的能力与权限表述须符合当前运行时，不把意识、情感或虚构能力写成事实。

## 证据与隐私

来源限于本轮明确陈述、授权材料及当前可验证的环境事实。草稿按以下等级整理：

- `confirmed`：用户明确陈述或可验证的直接证据。旧文件只能证明曾有这条记录；易变事实还需确认有效性。
- `inferred`：由行为样本推断。会影响协作时向用户自然复述，确认后再写成用户事实。
- `unknown`：没有足够证据，省略。

每条用户信息同时满足：会改变协作行为、值得在多数会话读取、用户已提供或确认。一次任务、短期情绪和无关传记细节留在本轮或相应项目中。

密钥、口令、证件号、精确住址、私密健康信息及无关第三方隐私不进入文件对；敏感值也不复制到变更摘要或历史文件。姓名、路径、语言或单次行为不能作为敏感属性的推断依据。

## 更新触发与差异

| 触发 | 处理 |
| --- | --- |
| 用户明确更正长期背景、协作偏好或确认边界 | 对照 `USER.md` 找到原条目，按新要求更新 |
| 用户明确调整 Agent 角色、原则、语气或边界 | 更新 `SOUL.md` 的相关条目，检查与 USER、IDENTITY、AGENTS 的一致性 |
| 当前维护流程发现可核实的稳定新信息或已失效内容 | 检查是否改变协作行为；在已有维护授权范围内更新对应文件 |
| 仅有行为推断、适用范围不明或相互矛盾的证据 | 提出具体待确认差异，原条目保持不变 |
| 新信息已被原文表达，或仅适用于本次任务 | 本轮使用相应上下文，持久文件保持不变 |

执行更新时，从当前请求或既有工作区维护约定判断写入授权；已有授权且差异明确时直接完成编辑与验证，不再次要求用户运行本 skill 或确认同一变更。发现候选信息不等于获得新的写入范围。普通对话中的一次纠正，只有明确具有长期适用性时才进入画像。

将新证据映射为原条目的新增、替换或清退，沿用既有有效结构。可以只更新一份文件，另一份用于一致性检查；用户偏好变化本身不构成重写 Agent 角色的理由。局部更新不重跑完整建档访谈，也不从空模板重建有效文件。若配对文件缺失，只在创建范围与证据都具备时补建，否则报告缺口。

批量维护仍按下述存量规则整理整份授权文件。完成更新须落盘实际差异并通过验证；有未决项时分别报告已完成部分与未完成部分，无差异时保持文件和日期不变。

## 存量维护与容量

两份正文都只表达当前有效状态。每次更新依次处理：

1. **保留**仍有效且会影响协作的条目。主要角色、长期项目等半稳定信息标注最近实质确认或变更日期，例如 `2026-09-06 · active — 正在设计初学者课程`；仅运行维护不刷新日期。
2. **合并**同文件及跨文件的重复含义。行为相同的改写合为一条，保留必要适用条件；不同条件下的偏好明确各自范围。
3. **替换**被新证据更正的旧版本。以本轮明确更正优先，其次采用有直接证据、日期更新且适用范围一致的版本；证据无法裁决时报告冲突，保持未决部分原状。
4. **清退**已失效、已完成、无协作价值或错误的条目。`superseded` 等历史状态从正文移出。局部更新以外发现的实质性删除或尚不确定的过期判断只报告，不能为了通过预算静默删掉用户条款。
5. **新增**现有条目无法表达、已确认且有持续行为价值的信息。优先修改原条目，避免以“补充规则”反复追加。

历史并非默认产物。旧版本仅有解释价值时，优先依靠已有版本记录；确需另存且目标位置在授权范围内时，将最小必要的历史说明移入按需资料。迁移后从正文移除旧文，仅在当前任务仍需回查时保留“何时读取 + 路径”的指针。没有迁移授权时交付具体建议，保留原文件并说明候选未完成；无需解释价值的已确认失效条目可直接清退。用户要求删除的信息不另行归档。

两份文件均受字符硬预算约束；默认值唯一配置在 [校验脚本](../scripts/validate_pair.py)，可用 `--help` 查看。计数包含 Markdown 标记与空白，按 Python 读取后的 Unicode 字符计数；它不是 token 数或平台声明的限制。

默认预算是本 skill 的紧凑度策略。用户明确指定字符预算时用 `--user-budget` / `--soul-budget` 传入；存在已核实且单位相同的更小运行时限制时进一步收紧。其他单位的运行时限制另行验证。禁止仅为通过校验擅自提高预算。

超限时依次合并重复、清退已确认失效条目、将分支细节迁到授权的按需位置、压缩措辞。仍超限则报告必要内容的取舍；保留有效含义优先于机械截断。预算是上限，不是需要填满的额度。

## 平台适配

默认沿用 OpenClaw 兼容文件分工。涉及真实路径、加载行为或平台容量时，核对当前配置与运行时文档；本 skill 不创建后台监听、定时任务或无限追加日志。
