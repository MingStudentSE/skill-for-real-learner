# Setup Wiki

直接维护用户知识库，以库根为一个 OKF 包。系统目录是参考布局，用户的当前要求和已有有效约定优先。保留原笔记正文、目录与 Obsidian 使用效果。

## 1. 定位知识库

解析用户指定的库根并读取现有 `AGENTS.md`、根索引和系统规则。路径未明确时只询问路径，不把当前 skill 仓库当成目标。新建库和已有库使用同一流程；仅要求检查时保持只读，最后报告差异。

按 [搭建与检查](references/setup.md) 盘点全部 Markdown、保留文件名冲突和实际规则／画像位置，形成修改清单。依用户授权推进可恢复的修改；含义不明的目标、内容取舍或应用管理文件只暂停受影响部分。

## 2. 建立系统与规则

按搭建参考复用实际系统目录；缺少时建立 `系统/规则/` 与 `系统/个人画像/`。不因参考布局而搬迁用户已有目录。

- 以 [日常维护规则模板](assets/maintenance.md.template) 建立或合并库内维护规则。
- 将 [属性规则](references/property-rules.md) 落成库内规则笔记，适配内部链接。复制和路径替换方式见搭建参考。
- 画像缺失或用户要求建立时，复用 `/user-profile-builder`，明确传入实际画像目录及库根上下文；已有有效画像保留。缺少此能力或人物信息时报告缺口，继续独立可完成部分，不生成虚构画像。

完成条件：库内规则能够独立指导日常维护，画像文件有真实内容或明确列为未完成项。

## 3. 规范笔记与导航

创建、修改或检查属性时读取属性规则：满足必需项，其余按用途与证据添加。字段结构查 [Spec §4](references/SPEC.md#4-concept-documents)，来源与核验查 [§5](references/SPEC.md#5-provenance-trust-and-lifecycle)，身份查 [§7](references/SPEC.md#7-actor-convention)；使用其他类型时定位相应章节。版本依据见 [来源记录](references/spec-source.md)。

按搭建参考建立或维护逐级 `index.md` 与根 `log.md`，保留人工导航、既有历史与可正常使用的 Obsidian 链接。只记录本次真实的重要变化，无变化时不重复写日志或刷新属性时间。

## 4. 生成入口并验证

写入或修改目标库 `AGENTS.md` 前，必须调用 `/writing-for-agents`，按 [生成规则](references/agents-template.md) 使用已确认的 [精简模板](assets/AGENTS.md.template)。额外约定由用户后续添加，已有用户内容保留。

执行搭建参考的验收清单，报告扫描范围、实际变更、结构／链接结果和未处理项。全部目标文件有对应处理结果、入口能到达真实规则与画像、旧内容和使用效果得到保留时，才报告搭建完成。检查模式只报告问题；局部完成不冒充全库完成。

日常维护由库内规则触发，不要求反复调用本入口。维护本 skill 时，使用 [行为评测](evals/scenarios.md) 检查空库、已有库、改名和重复运行。
