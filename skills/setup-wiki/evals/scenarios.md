# 行为评测

在临时知识库验证，不使用真实用户数据；检查可观察的产物和保留情况，不按措辞匹配打分。

| 场景 | 输入条件 | 应观察的结果 |
| --- | --- | --- |
| 空库搭建 | 已指定空目录，提供足够画像信息 | 系统规则、两份画像、逐级索引、根日志和 AGENTS 形成可走通的入口；普通笔记有 type，入口无画像 Skill 调用。 |
| 用户自定义结构 | 规则在 `管理中心 v2/运行/`，两份画像在不同子目录；入口有用户条款 | 模板替换为真实相对路径，用户条款保留；没有重新创建默认系统目录。 |
| 已有内容 | 原笔记有自定义 YAML、Wiki 链接、块嵌入；已有多天日志 | 保留原意和扩展，未知字段不丢失；日志历史不被初始化覆盖；结构合规与应用兼容分别报告。 |
| 保留文件名冲突 | `index.md` 是文章或仪表盘，另有指向其标题的入链 | 先保留内容，再建立索引并修复入链；无法判定语义时报告具体冲突，不覆盖。 |
| 重复执行与只读检查 | 已搭建且没有新事实；随后手动移动目录，再要求检查 | 无变化时不刷新属性或追加日志；检查阶段只报告陈旧路径，获得修复任务后沿用新位置。 |
| 范围与依赖缺口 | 未指定库根、缺画像信息／必要 Skill，或有不可处理的应用管理 Markdown | 不把开发仓库当目标；报告对应缺口，独立部分可继续；不声称全库完成。 |

模板机械验证覆盖默认路径与含中文、空格、不同层级的改名路径；校验变量全部替换、目标存在、YAML 类型有效。它不替代 Agent 实际搭建时的语义判断和 Obsidian 应用内检查。
