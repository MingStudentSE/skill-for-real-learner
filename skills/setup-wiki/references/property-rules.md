# 属性添加与调整规则

创建、修改或检查笔记属性时使用。先读正文、已有属性及本次变更；所有字段按实际用途与证据添加，满足规范必需项，保留有效的既有属性和自定义字段。用途或取值不明确的可选字段省略，不填占位值。

## 按用途选择

下表是判断规则，不是固定模板或字段白名单。字段结构查 [Spec §4](SPEC.md#4-concept-documents)，来源／信任／生命周期查 [§5](SPEC.md#5-provenance-trust-and-lifecycle)。

| 属性 | 何时添加或调整 |
| --- | --- |
| `type` | 普通知识文档必需，按实际用途填写非空字符串；已有有效值保留，类型可扩展。 |
| `title` | 需要独立显示名称，或文件名不足以清楚识别内容。 |
| `description` | 有必要简短描述笔记内容时，依据正文写准确摘要，不限定为索引或搜索用途。 |
| `tags` | 有真实的跨目录分类或筛选需求，优先复用已有标签含义。 |
| `sources` | 需要追溯所依据的材料或关键结论；仅记录真实使用的来源。参考链接不自动等于论据。 |
| `generated` | 需要记录当前内容如何产生，Agent 新建或实质改写是典型触发。记录实际生成者和时间；导入、重排、补格式不能冒充内容产生事件。 |
| `verified` | 实际核验内容后记录核验者和时间；读过、排版或格式检查不算知识核验，Agent 不冒用人工身份。 |
| `status` | 草稿、可用或弃用的区分会影响维护和使用。依真实状态判断，不在迁移时批量宣称内容已稳定。 |
| `stale_after` | 有明确有效期或已确定过时边界，按实际要求设置。 |
| `resource` | 需要指明笔记所描述的具体资源；材料来源使用 `sources`。 |

`index.md`、`log.md` 使用各自格式，不加普通笔记属性；只有包根索引可声明 `okf_version`。见 [Spec §8](SPEC.md#8-index-files)、[§9](SPEC.md#9-log-files)。特定类型的条件必需项在选用时查对应章节，例如 [§10](SPEC.md#10-attested-computations-concept)。

## 修改与检查

选用可选字段后满足其内部约束，身份与时间格式查 [Spec §7](SPEC.md#7-actor-convention) 和 §5。保持来源标识与正文引用一致，缺失的历史、作者或使用数据不猜测。

旧核验记录不证明新内容已核验；只有真实的新生成或核验事件才能更新对应时间。重复执行且无新事件时保持属性不变。

字段增补或调整先检查受影响的笔记、索引、查询和模板；更新库级含义时同步规则与重要变更日志。扩展字段先检查已有字段能否表达同一含义。验证 YAML 可解析、取值有依据、旧信息未丢失、引用仍有效；单纯属性维护保留正文和 Obsidian 使用效果。
