# 学习模型格式

学习模型是一份指定材料的可学习版本：保留材料章节顺序和完整内容地图，同时补足前置知识、概念关系和难点。它不记录学习者的过程、表现或掌握程度。

模型默认放在 `./learning-models/` 下，文件名使用 `<YYYY-MM-DD>-<topic>.md`。目录不存在时再创建。

## 总体结构

```md
# 学习模型：<材料标题>

## 材料与覆盖范围

- **材料：** <作者/讲者、版本、链接或文件>
- **模型目的：** <这份材料主要想让读者理解什么>
- **假定起点：** <已知背景；没有则写零基础假定>
- **已建模范围：** <章/节/页码/时间戳>
- **待覆盖范围：** <尚未实际处理的部分；完整时写“无”>

## 内容总览

1. **第 1 章：<标题>** — <这一章解决什么；核心 | 延伸；来源定位>
2. **第 2 章：<标题>** — <这一章怎样承接上一章；核心 | 延伸；来源定位>

## 读这份材料前，先补的背景

### <前置知识>

- **人话解释：** <读者先要懂什么>
- **为什么这里需要它：** <它会帮助读懂哪些章节>
- **还需要系统学习时：** <交给 teach 的范围；没有则省略>

## 第 1 章：<原章节标题>

### 这一章在讲什么

<用学习者语言概括本章，写出它与上一章的衔接。>

### 内容模型

- **核心内容**
  - **原材料内容：** <作者或讲者明确提出的观点、逻辑、案例作用>
  - **补充解释：** <为读懂它补的背景、因果或通俗表达>
- **延伸内容**
  - <仍需保留的细节、案例或进一步推导>

### 关键概念与关系

**<概念>**：<先用人话解释它是什么，再说明本章中有什么用。>
_不要混为一谈_：<相近但不同的概念>

<用箭头、表格或短层级说明关系，例如：概念 A → 造成概念 B → 用概念 C 解释。>

### 容易卡住的地方

#### <难点>

- **为什么难：** <抽象、隐含关系、反直觉或背景缺失>
- **这样理解：** <人话拆解>
- **常见误解：** <不该怎么理解>
- **小例子或反例：** <贴近本章的短例子>
- **回到原文：** <章、节、页码、时间戳或锚点>

### 来源导航

- <章、节、页码、时间戳或锚点>

## 章节之间的总关系

<用原材料顺序串起章节的承接、依赖或推导；必要时用小图或表。>

## 修订记录

- <日期>：<新增覆盖范围、修正补充解释或更新来源定位>
```

长材料先写“材料与覆盖范围”和“内容总览”，再逐步新增已实际处理的章节。短材料可以省略空章节，但必须保留范围、章节/段落模型、难点和来源导航。

## 建模规则

- **遵循内容顺序。** 按原材料章节或段落排列；不要为了追求漂亮结构而重排作者的论述。章节间的关系写在摘要和总关系中。
- **完整不等于逐句复述。** 每个已覆盖章节保留核心论点、逻辑、案例作用和必要的延伸细节；删去不会改变理解的重复表述。
- **分清来源。** 原材料内容只写来源实际表达的意思；补充解释明确标出，不冒充原话。长引用不作为总结替代品。
- **先让人读懂。** 每个关键术语先给人话解释，再给它的边界和在本章中的作用。用例子解释难点，而不是用更多术语解释术语。
- **如实标记范围。** 没有实际读到的章节只能出现在待覆盖范围或目录，不得写成已建模。
- **让 teach 接得住。** 让 teach 能从模型直接找到材料范围、核心内容、前置知识桥和难点；不要写练习、学习者评价或掌握结论。
