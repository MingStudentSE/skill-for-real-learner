# 概念学习卡

将一个已选定的笔记片段加工为一张能帮助学习者理解、区分、关联并尝试使用概念的卡片。卡片的目的不是复述笔记，而是让概念回答一个真实问题，并保留它仍然未知的边界。

本 skill 使用以下可执行判断：从具体问题而非术语出发；对关键概念做到一字一义；只连接理解当前概念所必需的少量“概念亲戚”；暂停输入并把概念接到经验、判断和行动上；把来源事实、教学解释与未验证假设分开。需要完整格式时，读取 [卡片格式](references/card-format.md)；交付前按 [质量检查](references/quality-rubric.md) 自检。

## 适用边界

在用户已经指定**一个概念及其笔记范围**时运行。有效输入包括：

- 一段粘贴的笔记；
- 笔记路径加标题、引用块、行号或明确段落；
- 已有材料模型中一个点名的概念。

如果用户只给出一篇包含多个概念的笔记，或说“把这一节做成卡片”但不能确定目标概念，只问一个问题：这次要做哪一个概念？不要擅自扩展为概念地图或多张卡片。

## 制作流程

1. **锁定范围。** 读取用户选中的段落，以及确认该段含义所需的最小标题和相邻上下文。记录来源路径、标题、页码、行号或其他可回溯锚点；无法得到精确定位时，标明“来源定位待补”。不要扫描整个笔记库。
2. **找出基本问题。** 从片段中提取概念试图解释、判断或改变的现象。优先写成“在什么情境下，如何判断/行动”的问题；原文没有提供时写“待补”，不要捏造用户的真实困扰。
3. **澄清一字一义。** 分别写出通用定义、当前片段中的含义、关键机制或因果链，以及“它不是什么/何时不适用”。原有定义足够准确时沿用；只有概念必须适配用户明确给出的语境时，才提供标为“个人工作定义”的暂定表述。
4. **建立最小概念束。** 选择 2–4 个对理解或使用最关键的相关概念，标明关系类型，例如前提、组成、因果、对比或应用条件。用一条关系链或小表展示，不罗列知识网络。
5. **让概念落地。** 给出一个贴合来源的正例与一个容易混淆的反例。若用户提供了自己的场景，将其转成一个最小的 `输入 → 判断 → 行动` 自测；没有场景时保留可填写的场景槽，不能编造个人经历。
6. **诚实标注证据。** 将卡片中的断言分为“来源事实”“教学解释”“学习者假设/个人工作定义”和“未知或待验证”。来源笔记本身若是推断，不能升级为事实。缺少定义、反例或适用条件所必需的资料时，明确缺口，并只问用户是否提供来源或授权寻找可靠资料。
7. **交付或保存。** 默认在对话中交付完整 Markdown 卡片。用户明确指定新文件路径或要求保存时才写入；目标文件已存在时不覆盖，先说明冲突并询问处理方式。若用户要求改写既有笔记，先展示拟修改范围并获得确认。

## 输出与质量门

使用 `references/card-format.md` 的模板。根据输入删去没有可靠依据的内容，而不是用空洞文字填满；保留“待补”提示即可。

交付前读取 `references/quality-rubric.md`，确认卡片至少拥有：一个明确的问题、一个边界清楚的定义、少量有标签的关系、一个可辨别的正反例、一个不伪造的判断/行动检验，以及来源和证据层级。不要把“卡片完成”写成“已掌握”；只有学习者的独立解释、判断或迁移表现才是后续 `study-review` 可用的学习证据。

概念卡默认是理解和判断工件，不自动成为 `learning-records/`、任务或学习模型。
