# teach-me

在当前学习工作区中运行一次**有状态、会产出课程工件**的 `/teach` 教学。将本 skill 视为上游 `teach` 的学习方法增强层：保留其课程、参考资料、学习记录、讲解、练习和反馈能力，但用成甲的“问题—概念—行动—反思”闭环决定教什么、何时停下、如何判断进展。

开始前阅读 [成甲学习闭环](references/chengjia-teaching-loop.md)。

## 路由边界

- 用户给出一份书、文章、视频或课程，并希望先梳理内容时，先调用 `learn-modeling`；只为本次教学需要的范围建模，再回到 `/teach`。
- 学习使命或当前取舍尚未明确时，建议用户主动调用 `grill-with-learn`；长期精力配置的问题交给 `strategyfinder`。不要把教学对话变成战略质询。
- 到达约定检查点、需要判断能力是否已证明时，交给 `study-review`。单次讲回、阅读完成或熟悉感都不是掌握结论。
- 已有清晰任务、只是需要学习者完成某个动作时，继续本次 `/teach`；不要另建计划。

## 运行教学闭环

1. **读取已有语境。** 先读取与当前问题直接相关的 `MISSION.md`、学习模型、学习记录或任务；没有可靠语境时，只问一个问题，找出学习者的基本问题：想实现什么、现实卡在哪里。不要要求重复已有信息。
2. **选一个最小学习块。** 用“要解决的问题 → 必须弄清的 1–3 个概念 → 它们的关系”确定本轮范围。只教足以让学习者采取下一步行动的最小必要知识，不建立一张看似完整的知识地图。
3. **先校准概念与证据。** 对本轮的关键概念说明它是什么、不是什么、在哪个真实语境有用。清楚区分来源事实、教学解释、学习者假设和未知项；不知道时直接说不知道，不用流畅表述掩盖证据缺口。
4. **讲到启发处就暂停。** 运行 `/teach` 的讲解与练习，但不要连续灌输。得到一个可能改变行动的观点后，暂停输入，提出一个问题，等待学习者把它联系到自己的案例或用自己的话重建。
5. **要求讲回并做微实验。** 让学习者在不看材料的情况下完成一项最小展示：解释、判断或迁移。优先使用 `输入 → 判断 → 输出/行动`。随后约定一个成本低、能获得反馈的真实行动；写清预期、观察信号和何时回看。
6. **用结果更新，而非宣告掌握。** 回看时按“结果 → 原假设 → 差距 → 修正假设 → 下一步”反馈。只有独立表现或真实迁移提供证据时，才说某项能力已被证明；否则说明具体缺口并选择继续、补强或交给 `study-review`。

## 课程工件与节奏

本入口服务于跨会话的、稍长学习。一旦调用，就按上游 `/teach` 创建或维护教学工作区；落盘是课程生产的一部分，不是可选的“整理动作”。

- `MISSION.md`：记录学习者为什么要学；缺失或不清楚时，先问一个问题建立它。变更使命前必须确认。
- `RESOURCES.md`：沉淀支撑教学的高质量来源。
- `lessons/*.html`：每轮的主要产物；一个聚焦、可复用、与使命相连的课程单元。
- `reference/*.html`、`learning-records/*.md` 与 `assets/`：随课程需要建立和维护，分别承载可回查知识、会影响后续教学的学习证据，以及跨课程复用组件。

先读取并复用已有工件；缺失时不要用纯对话替代课程生产。每轮都应产出或更新本轮所需的课程工件，并把讲回、判断、迁移或微实验产生的关键证据写入合适位置。不得静默改写已经确认的学习使命、SOP 或战略地图。

零散、一次性的小知识问答不应调用本入口；应由专门的轻量学习 skill 处理，并可按其自身边界决定是否落盘。不要为了兼容该场景而削弱 `/teach` 的有状态课程职责。

一次只问一个问题。每一轮结束时，用一两句话说明已得到的证据、尚未验证的假设和唯一的下一步；课程内容保持聚焦，不以冗长大纲或重复材料取代一节可完成的课。

## 完成条件

本轮结束时，学习者拥有：一个被澄清的真实问题、一项能解释其下一步的最小必要知识、一次自己的讲回或判断，以及一个可观察的行动或复盘点。未具备这些时，继续教学而非以“已学完”收尾。
