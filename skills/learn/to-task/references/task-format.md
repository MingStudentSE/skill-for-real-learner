# 编号任务格式

每个任务单独保存于当前项目的 `tasks/01-标题.md`。编号以文件名和标题表达，不另设重复字段。沿用已有目录；实际文件链接相对任务位置计算。计划在对话中时，将相关目标和检验标准简要融入“为什么做”；有实际文件时可附链接。

编号是稳定身份，新增递增，不复用、补缺或重编号。归档、取消和已知分配历史参与最大编号核对。拆分时保留原任务与替代关系，为新增任务续号。

## 默认：简洁核心

简单任务只用以下格式。将必要材料放在动作旁，将证据和反馈标准放在完成条件旁；无需另列行动、产出、验收、证据、反馈等重复字段。无需填写“无”、空表或尚未发生的执行记录。

```md
# 01：<动作与产出>

- **为什么做：** <对应计划中的主要问题或目标，当前要改善什么>
- **先做什么：** <用什么实际输入，立即做哪个具体动作>
- **留下什么：** <一份可查看、演示或继续使用的结果>
- **怎样判断完成：** <可观察标准及必要的独立表现；需要反馈时注明由谁或按什么检查>
- **预计投入：** <如 15–25 分钟，包含检查与必要修订>
- **状态：** 已计划
```

例如：

```md
# 01：解释留存率口径并核对一个样本

- **为什么做：** 周报需要准确解释留存变化，先排除对分子、分母的误解。
- **先做什么：** 打开团队现有指标说明，选取其中一个有原始数据的样本，写出计算式。
- **留下什么：** 一次样本计算和一段自己的口径解释。
- **怎样判断完成：** 计算与原始数据一致，不看说明能解释分子、分母及时间范围；不一致时对照说明修正。
- **预计投入：** 15–25 分钟。
- **状态：** 已计划
```

## 按需展开

只有存在多步骤、重要依赖或较高不确定性时，才展开相关部分；按需要增加有序列表或步骤表，不要求把所有可选字段加齐。

- **多步骤：** 将“先做什么”改为“怎么做”，用列表或下表写清动作衔接；第一步就是起手动作，不再重复“立即开始”。整体产出与完成标准保留在核心字段，步骤只记局部结果和检查。
- **重要依赖：** 在相关步骤前写出需要的任务编号及实际链接，注明必须取得的产出或证据；材料未齐时说明取得动作与阻塞点。
- **判断或试错：** 在相关步骤或完成条件旁写明需要比较“原先判断／假设、实际结果与差距、下一轮改变的判断或动作”。原先想法尚不清楚时先观察，不代填。
- **迁移与复用：** 对重要、反复使用的能力，按需增加换材料、变条件或反例检查，写出要观察什么；把检验计入预算。只保留值得复用的方法或适用边界，无需额外制造笔记任务，未经检验的迁移标待验证。

| 步骤 | 输入与具体动作 | 局部结果、检查及未达标处理 | 预计投入 |
| --- | --- | --- | --- |
| 1 | <所需输入与动作> | <留下什么；按什么继续或调整> | <区间> |
| 2 | <利用上一步结果做什么> | <局部结果及反馈> | <区间> |

预计投入只在核心字段写一次总预算；展开步骤时可列分步区间，不再新增“投入合计”字段。按区间上限核对可用时间，首次执行后记录实际耗时并校准后续估计；估计不等于完成时限。

## 执行后按需记录

有实际执行或证据时才追加记录：日期、实际产出或表现、已满足与未满足的标准、状态变化依据及下一步。涉及判断校正时保留原先假设、结果差距和改变的动作；实际耗时用于校准估计。已有详细记录时链接即可，不重复抄写。

状态沿用：已计划、进行中、已收集证据、需补强、已完成、已延期、已取消。只有全部既定验收有充分证据时才标为已完成；局部步骤达标不自动等于整个任务完成。保留原有标准、证据和用户自定义，不为套用新模板重写历史任务。
