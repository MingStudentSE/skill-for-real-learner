# 生成学习任务

把当前对话中已明确的学习计划拆成可执行、可验收的编号任务；已有计划文件可作为补充依据。

## 1. 定位项目与计划

先读取根 `AGENTS.md` 的配置指针及其指向的本地学习配置，恢复 workspace（工作空间根）与 project（当前学习项目根）、项目识别方式和各状态路径；默认配置位置为 `docs/agents/learning.md`。workspace 级路径相对工作空间，project 级路径相对当前项目，已有配置的路径基准优先。保留已有文件名和布局，不因默认名称不存在创建第二套状态。

根据用户明确指定的项目路径、当前目录所属项目、本轮已明确且仍有效的项目上下文、已核对的唯一项目依次定位项目。根目录有多个候选项目、线索冲突或无法确定时，只询问项目并等待，不按最近修改时间猜选。仅在已有配置或学习工件明确证明根目录本身为项目时沿用根项目，不自动把公共根目录当作项目。无配置时，可使用用户明确指定或当前目录已有学习工件所确认的项目；仍无法确定则询问，无需强制先运行 setup。

优先沿用当前对话中已经讨论明确的计划，恢复目标、当前阶段、起点、可用时间与检验标准；信息已足够时直接拆解，不要求计划先保存为文件，也不要求由特定入口生成。按需读取已有计划文件、任务目录与相关学习记录，补充约束并核对已有证据。对话与文件冲突时，以用户最新明确决定为准；仍不明确时只询问影响拆解的关键分歧。缺少可识别计划时，询问要拆解的计划内容；请求改变原计划范围时先澄清本次采用的范围，避免默默扩展。无需补写使命或计划文件。完成条件：当前采用的计划、唯一项目和任务输出位置已确定，现有任务编号与证据已核对。

## 2. 从计划拆解任务

读取[编号任务格式](references/task-format.md)，按计划当前阶段拆解一批现实可行的任务。继承计划的时间、资源、起点和检验点；只问已有材料无法回答且会改变拆分的一个关键问题。远期保留在计划中，不凭空精排全部课程。

按以下顺序把计划编译为行动：

1. 从当前阶段检验点倒推最终要独立完成的表现，列出它需要的关键判断与基本操作；对照已有证据，只保留尚未具备或尚未验证的部分。起点不明时，安排计划内的小样尝试取证，不直接认定不会。
2. 围绕一个主要问题或可验收产出组织编号任务，允许综合运用多项能力；只有某项基本功反复阻塞整体表现时，才单独拆出练习。复杂任务再拆成有序步骤；步骤写成“在什么情境、用什么输入、做什么、留下什么、怎样判断可继续”。前一步产出作为后一步输入。
3. 把资料阅读放到具体步骤需要的位置，限定章节、片段或要回答的问题；实践技能可先观察一个可获得的真实示范，再尝试、比较和修正。概念学习可用解释、辨析或推演形成同样可观察的闭环。
4. 按任务或步骤估算投入，允许用区间表示不确定性，并按上限核对容量；首次执行后用实际耗时校准。让每次执行能在计划的一次可用时段内停在可恢复的产出上；较长步骤继续拆分，保留整体任务验收。把准备、尝试、反馈和修订都计入当前批次总量。超出容量时缩小批次，保留计划检验所需的完整闭环。
5. 对涉及判断或试错的任务，设计“原先的判断或假设 → 实际结果与差距 → 下一轮改变的判断或动作”的反馈校正；未知想法标待观察，不替学习者编造。简单操作无需强填反思。对计划中重要且会反复使用的能力，按需用新材料、变化条件或反例检验方法的适用边界，将其计入预算；未检验时只记录待验证，不据单次成功宣称可迁移。
6. 检查依赖是否必要且无环：依赖说明需要上游哪份产出或哪条达标证据；可并行部分直接标明。资源缺失时写明取得方式与阻塞点，未经核对不编造材料、数据或反馈人。

完成条件：当前批次从计划检验点可倒推至第一步，学习者打开任务即可开始，无需再制定执行方案。颗粒度、反馈与拆解示例见[拆解依据与示例](references/decomposition.md)。

每个任务对应一个可验收行动单元，可分多次完成。默认使用“为什么做、先做什么、留下什么、怎样判断完成”的简洁核心，附预计投入与状态；只有多步骤、重要依赖或较高不确定性时才按需展开列表或步骤表。材料与依赖在需要时补充。将证据和反馈放在相应行动或验收旁，避免重复填表。优先独立解释、判断、迁移或真实反馈；阅读时长和课程数量不能代替能力证据。避开已有证据证明掌握的重复任务。

默认每个任务保存为当前项目 `tasks/01-标题.md`、`tasks/02-标题.md` 等。编号是项目内稳定标识：首次从 01 开始，新增使用所有已有、归档、取消任务及已知分配记录的最大编号加一，保留缺号，不复用编号，不为调整顺序重编号；达到 100 后继续递增。依赖用编号和实际相对链接表达，顺序调整通过依赖和任务说明表达。无法确认编号是否曾分配时，先询问，不填补空缺。重名编号或冲突先解决，不覆盖。

已有等价任务目录继续使用。已有单文件任务清单保留原文；需要转成编号文件时，先展示迁移映射并确认，保留旧内容及回查关系，不自动删除、搬移或重编号。

## 3. 展示并写入

展示具体编号、文件路径、计划关联、验收、依赖、投入和拟修改的既有任务，供用户确认；已有明确授权覆盖的内容可直接执行。只写入已确定的任务文件，保留已有证据、状态和用户自定义，避免重复拆解同一任务。

验证任务编号唯一且稳定、已有计划文件及依赖的相对链接有效、依赖无环，每个任务可追溯到实际计划的阶段与检验点。逐项检查步骤输入可获得、产出能衔接、继续条件与未达标处理明确，任务或步骤的估时区间与总预算一致，批次按上限仍符合可用时段；判断任务有可校正假设的反馈，迁移结论与实际检验范围一致；确认没有越出项目边界。报告新增和修改的任务、约束与未知，给出第一项可开始任务的具体起手动作；项目尚未成为明确上下文时同时说明项目路径。

完成条件：当前批次已写入项目任务目录，每项任务有可检查验收、计划关联和稳定编号，第一项可开始任务可被编号定位。
