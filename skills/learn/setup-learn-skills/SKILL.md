# setup-learn-skills

为用户工作空间建立支持一个或多个学习项目的本地环境：一个根 Agent 指令入口、公共学习配置、多个项目文件夹。采用“先检查现有约定 → 展示具体修改 → 确认后合并”的 setup 模式；保留用户命名与布局，重复运行只补缺项。

## 1. 读取已有约定

确认目标用户工作空间的绝对路径，读取已有根 `AGENTS.md`、`CLAUDE.md`、`docs/agents/learning.md` 及相关目录说明。核对学习项目文件夹、项目内计划、任务与教学工件的位置，以及本环境实际可用的学习 skills；只记录已验证存在的入口及其调用属性。

区分工作空间根与学习项目根：公共配置放在工作空间，使命、计划、`tasks/`、课程和学习证据放在各自项目。新布局使用一个根 `AGENTS.md` 和多个项目文件夹；单项目也沿用该结构。已有根项目或自定义布局保留，不自动搬迁；项目内不新增重复 `AGENTS.md`。

在配置中约定统一的项目定位顺序：用户明确指定的项目 → 当前目录所在项目 → 当前对话已明确且未被本次路径覆盖的项目 → 工作空间中唯一项目。仍有多个候选时询问项目，不能仅凭任务编号跨项目选择。项目路径以工作空间根解析，项目内状态路径以已选项目根解析。未来新增项目沿用同一布局，无需重新 setup。

复用已有文件名、目录与指令入口。若 `AGENTS.md` 已有到 `CLAUDE.md` 的引用，沿用该链；若只有 `CLAUDE.md`，优先在其中合并学习指针；两者都有时读完现有互引关系，选择一个权威位置，避免双份规则。确无指令文件时，才提议创建根 `AGENTS.md`。发现冲突只询问影响配置的一个关键选择。

本步完成：目标工作区、现有布局、指令权威位置和可用入口均已核对。

## 2. 展示可审阅草稿

读取[本地配置模板](references/learning-config.md)，按工作区现状填入具体路径和实际入口，展示每个待修改文件的新增、替换或保留内容。说明哪些路径只是未来工件的约定。先完成具体草稿，再请求确认；当前指令已明确授权具体路径和内容时，直接应用该范围内的草稿，无需重复询问。仅说“初始化”不视为授权覆盖已有自定义。

配置输出限于 `docs/agents/learning.md` 和一个根指令入口中的学习管理区块。项目计划 `LEARNING-PLAN.md`、任务目录 `tasks/`、使命、画像、课程和学习记录由后续入口在确有需要时创建；本入口不预造项目、任务或学习状态，也不自动运行其他入口。记录交接约定：`to-plan` 在项目内制定计划，`to-task` 根据计划生成 `tasks/01-标题.md`、`02-标题.md` 等独立任务，用户通过 `/teach-me 01` 开始或继续对应任务。编号只在所属项目内解析。已有单文件任务清单保留，由用户显式运行 `to-task` 时处理迁移。

## 3. 合并并验证

在指令权威文件内使用以下唯一管理区块：

```md
<!-- learn-skills:begin -->
开展本工作区的学习、教学、计划或复盘前，读取 [本地学习配置](docs/agents/learning.md)，按其中的布局、状态路径与阅读规则执行。
<!-- learn-skills:end -->
```

仅更新已有同名管理区块；没有时追加一次，保留区块外全部内容。根入口有等价指针时复用它。对配置文件逐项合并：保留用户定义的路径、命名、阅读规则和扩展章节，只补已确认缺项。存在冲突时展示差异并等待；无法识别原区块边界时保持原文并报告。重复运行且配置已满足要求时报告无变化。

验证根指针能定位配置，项目目录相对工作空间根、状态路径相对对应项目根，单项目和多项目均能唯一定位或明确提示选择；核对 `tasks/NN-标题.md` 与 `/teach-me NN` 的交接规则、可用 skills 的实际安装与调用属性。未来项目和状态路径允许尚不存在，明确标注；保存的安装检查只代表本次环境，调用时以当前可用工具为准。报告实际修改、保留的自定义与未解决项。只把已完成核验的配置称为就绪。
