# 概念卡片格式

每张卡只解释一个概念。保留来源与证据标记；对当前输入无可靠依据的部分，填“待补”或省略，不要补造细节。

```md
---
type: concept-card
concept: <概念名>
source:
  - <笔记路径或材料> # <标题、页码、行号或其他锚点>
status: draft | tested
---

# <概念名>

> **一句话把手：** <这个概念如何帮助人在某类情境作出更好的判断或行动。>

## 它要回答的基本问题

- **情境：** <原片段描述的现象；没有可靠语境则写“待补”。>
- **问题：** <在什么条件下，如何判断或行动？>

## 一字一义

- **通用定义：** <来源支持的定义；避免循环定义。>
- **在当前笔记中：** <它在此处具体指什么。>
- **关键机制：** <条件 → 过程 → 结果，或最短因果链。>
- **不是什么／边界：** <最容易混淆的相邻概念、失效条件或不可推出的结论。>
- **个人工作定义：** <仅在用户给出自身语境且确有必要时填写，并标为待验证。>

## 最小概念束

| 相关概念 | 关系 | 为什么此处需要它 |
| --- | --- | --- |
| <概念 A> | 前提／组成／因果／对比／应用条件 | <一句说明> |
| <概念 B> | … | … |

**关系链：** `<概念或条件> → <当前概念> → <判断或结果>`

## 例子与反例

- **正例：** <满足关键条件时，概念如何解释或指导一个具体判断。>
- **易混淆反例：** <表面相似、但缺少关键条件的情况，以及为什么不适用。>

## 在我的情境中检验

- **场景：** <用户给出的场景；否则“待补：给出一个近期情境”。>
- **输入：** <我看到了什么信息或约束？>
- **判断：** <这个概念使我区分或选择什么？理由是什么？>
- **行动：** <下一步最小尝试、观察信号或需要补查的资料。>

## 知识边界

- **来源事实：** <原笔记或明确来源直接支持的内容。>
- **教学解释：** <为说明关系而作的简化、类比或推导。>
- **学习者假设／个人工作定义：** <仍需检验的判断。>
- **未知／待验证：** <不能由当前片段回答的问题。>

## 来源导航

- <来源路径> — <标题、页码、行号或段落锚点>
```

## 填写规则

- 将“通用定义”和“个人工作定义”分开。后者服务当前问题，不替代专业或原作者定义。
- 关系数量通常为 2–4 个。只有新关系会改变解释、判断或行动时才加入。
- 正例与反例必须共享相近表面特征，关键条件不同；不要只写“成功/失败”的结果。
- `status: draft` 表示尚未在个人情境中检验；`tested` 只表示有一次明确检验记录，不等于掌握。
- 不复制大段原文。用自己的话概括，必要引用保持短小并附来源锚点。
