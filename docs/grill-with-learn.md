## 它做什么

`grill-with-learn` 用持续追问澄清学习使命或当前学习决策。它运行上游的 `grilling`，并在需要理解指定材料时复用 [`learn-modeling`](learn-modeling.md)。

它的价值在于把模糊的“我想学 X”变成可以取舍、可以规划的问题，而不是立即给出一份看似完整的课程表。

## 何时使用

你通过输入 `/grill-with-learn` 调用它；模型不会自行调用。

| 你的处境               | 该选什么                                        |
| ------------------ | ------------------------------------------- |
| 学习使命、现实卡点或当前决策还说不清 | `/grill-with-learn`                         |
| 真正的问题是长期方向和精力配置    | [`strategyfinder`](strategyfinder.md)       |
| 已有共识，只需固定阶段方法      | [`to-sop`](to-sop.md)                       |
| 只想立刻学懂一个已点名概念      | [`learn-one-concept`](learn-one-concept.md) |

## 用质询找到真正的问题

它的核心是**质询**：持续追问不是为了收集更多偏好，而是为了找出阻塞现实行动的决定性问题、边界和取舍。若一个来源材料本身看不懂，先建立足够的学习模型，再继续围绕学习者自己的决定讨论。

## 常见问题

**它和 `strategyfinder` 有什么不同？**

它澄清一个学习使命或当前决定；`strategyfinder` 维护跨阶段的长期战略地图与重大取舍。

**质询结束后会自动生成 SOP 吗？**

不会。若已经形成稳定方向，你可以选择手动运行 [`to-sop`](to-sop.md)。

## 有效的信号

- 学习者能够用自己的话说清想解决的真实问题与当前选择。
- 已知事实、偏好、假设和未知不再混在一起。
- 会话结束时留下一个可以由学习者显式选择的下一步，而不是被自动推进。

## 它在流程中的位置

这是学习流程的轻量入口之一。它常在 [`to-sop`](to-sop.md) 之前帮助形成足够清晰的输入，也可独立用于重新审视一个当前决策。需要选择入口时使用 [`ask-ming`](ask-ming.md)。
