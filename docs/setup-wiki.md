# setup-wiki

用 `/setup-wiki <目标知识库路径>` 为新建或已有知识库搭建维护机制；也可以明确要求只检查，或修复已有机制。它适合解决“AI 不知道该读哪些规则”“笔记变了而索引没变”“已有库需要统一 OKF 属性”等问题。

它建立系统规则、两份画像的读取入口、根 `AGENTS.md`、各级索引和根日志。目录只是参考：用户可以改名、拆分或调整结构，后续执行沿用真实布局。原笔记仍是正文所在，不另外导出一套知识副本。

属性按用途和证据添加，不要求每篇笔记填满字段。索引逐级展开，日志记录重要变化。完整 OKF Spec 随 Skill 保存，日常规则落在用户知识库中；规则和入口不会提供后台监听。

`AGENTS.md` 使用已确认的精简模板，生成时替换实际路径。它读取 `USER.md`、`SOUL.md` 和按任务需要的索引、规则，不包含画像更新 Skill 调用；额外约定由用户后续添加。写入口需要 `writing-for-agents`，建立画像时复用 `user-profile-builder`，缺少依赖或必要信息会明确报告。

完成后应能观察到：入口指向真实画像与规则，索引对应实际内容，属性有依据，重要变化可从根日志追溯。已有历史、用户条款和 Obsidian 功能得到保留；无变化的再次执行不制造日志，不恢复用户改掉的默认目录。

它负责维护机制。内容建模交给 `learn-modeling`，任务规划和学习判断继续由对应入口负责。格式检查通过不等于内容正确，也不等于所有 Obsidian 扩展可以跨工具运行。

具体执行见 [SKILL.md](../skills/setup-wiki/SKILL.md)，生成入口见 [AGENTS.md 模板](../skills/setup-wiki/assets/AGENTS.md.template)。
