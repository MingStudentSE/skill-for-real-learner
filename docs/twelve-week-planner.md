## 它做什么

`twelve-week-planner` 把一个已经值得投入的重要项目变成可执行的十二周周期：选择一至两个可验收结果，把目标编译成带周次的关键战术，用 Model Week 检查现实容量，并在周期中用周记分、偏差诊断和变更控制持续指导。第十二周结束后，它还会区分结果与系统能力，完成第十三周结算。

它不是把年度任务压进三个月，也不是另一张完整待办清单。十二周只是默认控制窗口；真实反馈速度明显不同、关键战术无法进入日历或外部约束改变时，计划必须缩小、调整或暂停。

## 何时使用

你通过输入 `/twelve-week-planner` 调用它；模型不会自行调用。

| 你的处境 | 更合适的入口 |
| --- | --- |
| 已经有重要项目，需要建立或运行十二周执行周期 | `/twelve-week-planner` |
| 长期方向、重大取舍或精力配置仍未决定 | [`strategyfinder`](strategyfinder.md) |
| 学习阶段的方法、资源策略和检查点尚未形成 | [`to-sop`](to-sop.md) |
| 只需把学习 SOP 或明确任务简报拆成当前一批学习任务 | [`to-task`](to-task.md) |
| 要检验一个概念或能力是否真的掌握 | [`study-review`](study-review.md) |

一次会议、普通待办、提醒设置，以及无需周期反馈的单次任务，不需要进入十二周系统。

## 它怎样指导一个周期

新周期先确认方向和当前项目块，再产生可判定目标、少量高杠杆战术与前置依赖。随后，计划必须在真实日历中为固定义务、战略工作、缓冲和恢复找到位置；日历放不下时，先减量而不是依赖意志力。

周期中每周先面对上一周事实，再从周期计划抽取本周关键战术。执行率、事前指标和事后结果分开记录：低执行时先恢复关键行动，高执行却持续没有结果时才更有依据修改策略。疾病、照护、新机会或组织变化则走最小改动阶梯，不用重启清除低分。

## 有效的信号

- 周期末结果可由第三方判断完成或未完成，并有明确不做范围。
- 每项关键战术有动作、频率或截止周、前置依赖与负责人。
- Model Week 能指出战术的真实时间落点，并保留必要缓冲和恢复。
- 周记分没有把执行率、投入和结果混成一个数字。
- 计划调整写清改变了什么、放弃了什么、新截止和回归点。
- 第十三周如实冻结结果，同时提炼下一周期要保留、修改、停止和验证的内容。

## 它在流程中的位置

`strategyfinder` 决定长期值得投入的方向，`twelve-week-planner` 负责让一个已选项目在短反馈窗口中真正运行。学习型项目仍可用 [`to-sop`](to-sop.md) 定义阶段方法、用 [`to-task`](to-task.md) 规划学习任务、用 [`study-review`](study-review.md) 检验能力证据；十二周规划不替代这些工件，也不会自动启动它们。拿不准入口时先用 [`ask-ming`](ask-ming.md)。
