## 它做什么

`study-review` 先确定一项学习要证明的解释、判断或行动，再从已有作品、文件、回答与反馈中寻找独立表现；证据不足时，它会在当前对话中通过无提示展示和苏格拉底式追问补足证据，最后给出不超出证据的结论并校正相关学习设计。

它评估的是**实际表现**，不是课程数量、投入时长、笔记篇数或“感觉已经懂了”。文件来自哪个 skill 也不决定它是不是证据。

## 何时使用

你通过输入 `/study-review` 调用它；模型不会自行调用。

| 你的处境 | 该选什么 |
| --- | --- |
| 想检验自己是否真的理解一个点名概念，即使没有任何前序文件 | `/study-review` |
| 已有作品、练习、代码或反馈，想判断它们证明了什么 | `/study-review` |
| 到达学习检查点，需要据此校正课程、SOP 或任务 | `/study-review` |
| 想从讲解开始学懂一个概念，而不是先接受检验 | [`learn-one-concept`](learn-one-concept.md) |

用户提供参考材料时，审查以材料实际覆盖的定义、边界和关系为依据。没有材料时，会先建立足以公平检验的可靠标准。既有 `MISSION.md`、`LEARNING-SOP.md`、`TASKS.md`、学习模型或课程可以提供目标和原假设，但不是调用前提，也不自动证明掌握。

## 一条审查路径

每次复盘都经过同一条路径：

1. 把“我学会了吗”改写成一个可观察的能力主张。
2. 盘点已有材料中是否包含独立任务、作品、判断过程、迁移表现或外部反馈。
3. 证据不足时，在对话中安排一个最小展示，并根据首次回答追问依据、边界、反例或条件变化。
4. 分开记录独立答出、追问后澄清、提示后修正和教学后完成。
5. 给出“达到预期、部分达到、未达到预期或待验证”的逐项结论。
6. 有既有学习设计时，将证据送回学习模型/课程、SOP、TASKS、执行条件或使命/战略信号，并记录每个工件是保留、已确认并更新，还是交给后续决定。

现场取证会先收集无提示表现。后续问题根据学习者的回答逐步深入，不会预先给推荐答案，也不会把提示后的正确回答倒算成原有能力。

## 结论能说明什么

有学习前状态和后续表现时，复盘可以判断发生了什么变化，并据此校正学习内容、SOP、任务或执行条件。影响使命或长期取舍的证据只在本次复盘中记录为重审信号，`MISSION.md` 与 `STRATEGY-MAP.md` 保持原状，直到对应决策得到学习者确认。只有当前表现时，复盘仍可判断目前是否达到目标。

默认结论写入 `reviews/<date>-<checkpoint>.md`；用户只需要对话结论或当前环境不能写文件时，使用同一结构在对话中交付。

## 有效的信号

- 每项待证明能力都有明确情境、预期表现和判断依据。
- 每个非“待验证”结论都有对应的独立表现，而不是进度记录。
- 已有证据与现场取证都说明了能证明什么、不能证明什么。
- 所有提示和教学都有介入记录，没有污染首次表现。
- 每个相关既有工件都有“保留、已确认并更新或交给后续决定”的处理结果。
- 下一步针对已暴露的最小缺口，而不是笼统要求“继续学习”。

## 它在流程中的位置

它既可以独立检验一个概念，也可以在持续学习的检查点读取累计证据。它不承担从头教学：需要补学时，学习者可在复盘后手动进入 [`learn-one-concept`](learn-one-concept.md) 或 [`teach-me`](teach-me.md)；需要调整学习设计时，再自行选择 [`to-task`](to-task.md)、[`to-sop`](to-sop.md) 或其他入口。
