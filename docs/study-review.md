## 它做什么

`study-review` 审查一段学习是否真的改变了解释、判断或行动。它从真实表现和结果出发，产出 `reviews/<date>-<checkpoint>.md`，再决定应该校正学习模型/课程、SOP、任务设计、执行条件，还是先补收证据。

它评估的是**学习效果**，不是课程数量、投入时长、笔记篇数或“感觉已经懂了”。

## 何时使用

你通过输入 `/study-review` 调用它；模型不会自行调用。

| 你的处境 | 该选什么 |
| --- | --- |
| 已经过一段持续学习，积累了练习、产物或反馈 | `/study-review` |
| 只完成了一次阅读或一节课，尚无表现证据 | 继续学习或先设计最小展示 |
| 缺少 `MISSION.md` 或 `LEARNING-SOP.md` | [`to-sop`](to-sop.md) |
| 已有 SOP、尚未开始下一轮，且需要安排当前任务批次 | [`to-task`](to-task.md) |
| 长期战略受到反复新证据挑战 | 下次手动进入 [`strategyfinder`](strategyfinder.md) |

它不是每次学习后都必须运行的仪式；检查点应跟随有意义的能力簇、真实任务或一段练习。

## 前提条件

带上与本次内容直接相关的 `MISSION.md`、`LEARNING-SOP.md`、`TASKS.md`、学习模型、课程或参考资料、学习记录、真实练习产物和既往复盘。证据不足时可以得出“待验证”，而不是强行判定成败。

## 效果证据，而不是过程分数

它的核心是**效果证据**：过去在什么情境下作出什么判断或行动、当时依赖什么假设、学习改变了什么、现在有什么可观察结果。非“待验证”的结论必须有独立任务、脱稿重构或陌生情境判断等表现支撑。

差距沿着“结果 → 原假设 → 差距 → 修正假设 → 下一步”定位。诊断可以落在内容、SOP、任务、执行条件或证据不足，不能把所有问题都归因为学习者不够努力。

## 常见问题

**我感觉懂了，为什么还需要复盘？**

熟悉感不是独立表现。复盘要求把学习带来的改变和真实证据连起来，才能知道下一步该补内容还是改方法。

**一次表现不好会推翻整个战略吗？**

不会。它先校正最近一轮的学习设计；只有反复出现、会改变长期取舍的新信号，才在下一次 [`strategyfinder`](strategyfinder.md) 中讨论。

## 有效的信号

- 每个被审查单元都有明确的预期效果和诚实的状态：有效、部分有效、未产生预期效果或待验证。
- 每个非“待验证”结论都有对应的表现或反馈，而非进度记录。
- 复盘明确指出下一步应校正内容、SOP、任务，还是补收哪项证据。

## 它在流程中的位置

它是阶段性效果检查，而不是教学链条的自动终点。它读取前序工件并给出校正依据；学习者再自行选择更新 [`to-task`](to-task.md)、[`to-sop`](to-sop.md)、课程内容，或在必要时重审 [`strategyfinder`](strategyfinder.md)。
