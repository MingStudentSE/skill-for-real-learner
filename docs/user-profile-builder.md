# user-profile-builder

用 `/user-profile-builder <目标画像目录>` 建立或更新用户协作偏好与 Agent 角色；加上“只审查”可检查已有文件的重复、冲突和膨胀。它也能把混在一段提示词中的两类内容拆开，或被知识库流程按需复用。

后续更新是它的常规职责。例如：`/user-profile-builder <目标画像目录> 更新：以后先给结论，再解释依据`。它会读取原文，修改对应条目，保留其他有效内容，并完成验证；只调整用户偏好时，通常只需改 `USER.md`。调整 Agent 角色与原则时，同样由它更新 `SOUL.md`。

已有工作区维护约定授权更新画像时，流程发现稳定新信息即可复用它，无需每次重新建档或再次授权同一操作。推断与临时要求先留在当前任务中；明确差异才进入持久文件。

`USER.md` 回答“怎样帮助这个人更有效”，`SOUL.md` 回答“这个 Agent 遇到分歧与风险时如何判断”。它适合长期协作规则，普通个人简介、人物模仿和完整工作区配置另有用途。

维护后的正文是一份当前视图：偏好改变时替换旧版本，重复表达合并，已确认失效的信息退出正文。历史有必要时放在授权的按需位置；同样的信息再次输入，不会刷新日期或追加记录。文件越用越多、旧偏好一直留在正文，都是需要重新审查的信号。

两份文件都有字符硬预算，超过预算必须整理或明确报告取舍。默认值来自 skill 的校验脚本，不代表平台限制，也不是应填满的目标。校验通过只证明机械检查通过；含义是否重复、事实是否过期仍需评审。

完成时应能看到：每条内容有行为价值和依据，职责分开，正文只保留有效信息，字符数在预算内，变更与待确认事项清楚。缺少证据时使用最小草稿，不靠补齐模板制造用户事实。

`setup-wiki` 负责知识库维护机制，可在需要画像时复用它；教学画像 `LEARNER-PROFILE.md` 仍由 `teach-me` 维护。这个 skill 自身不提供后台监听或自动记录每次对话。
