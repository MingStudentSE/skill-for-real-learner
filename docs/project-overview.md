# 项目全貌与阅读导航

本项目聚焦长期学习：在本地配置环境、澄清问题、制定学习计划、安排计划内任务，并通过教学与表现反馈持续推进。学习者显式决定何时进入下一步。

## 分类与能力

| 分类 | 内容 | 维护方式 |
| --- | --- | --- |
| [Learn](../skills/learn/README.md) | 本项目维护的 7 个学习能力 | 按学习流程演进 |
| [Up-stream](../skills/up-stream/README.md) | 官方 `grill-me` 与 `grilling` | 固定版本、原样同步 |
| [Deprecated](../skills/deprecated/README.md) | 退出当前发布范围的 7 个旧能力 | 保存历史，入口改名归档 |

共 9 个公开 skill：7 个由用户显式启动，2 个可复用能力。调用分类以 [skills 清单](../skills/README.md) 为准；目录分类说明来源与生命周期，调用分类说明谁可以启动。

## 典型使用

1. `/setup-learn-skills` 配置一个根 Agent 入口及单项目、多项目通用的本地环境。
2. `/grill-me` 澄清计划或决策；学习材料理解阻塞判断时，用 `/grill-with-learn` 按需复用建模。
3. `/to-plan` 定制学习目标、范围、路线、资源、节奏和检验点。
4. `/to-task` 根据项目计划生成 `tasks/01-标题.md`、`02-标题.md` 等有产出和验收条件的任务。
5. 在当前项目输入 `/teach-me 01` 开始或继续编号任务，教学、练习、检验并记录证据，将计划或任务调整建议交回对应入口。

`strategyfinder` 在长期方向、重大精力配置或高成本取舍需要决定时使用。它以 `grilling` 为主干，从实践及时间、金钱、精力投入与反馈分析候选方向，识别关键假设，按需查证外部事实并设计低成本真实测试；复盘后由用户决定加码、维持、缩小或暂停。仅在材料理解阻塞判断时加载 `learn-modeling`，不强制研究子代理、独立研究笔记或代码原型。`learn-modeling` 可直接点名，也可由学习流程按需复用。已有状态可直接续接对应环节，入口不会自动串联。

## 四个重要边界

| 信息 | 职责 |
| --- | --- |
| 环境配置 | 指明状态位置和工作区规则，不预造学习进度 |
| 学习计划与任务 | 分别表达路线和当前行动；任务必须属于计划 |
| 学习模型 | 解释内容、关系、边界和来源，不证明掌握 |
| 教学画像与学习记录 | 分别保存当前教学决定和持久表现证据 |

长期战略独立维护，不因一次练习表现自动改变。具体状态边界见 [ARTIFACTS](../skills/ARTIFACTS.md)，术语见 [CONTEXT](../CONTEXT.md)。

## 官方内容怎样接入

`grill-me` 和 `grilling` 是独立 skill。完整官方 `teach` 正文与四份格式放在 `teach-me` 的内部参考目录，外层读取它并增加本项目教学行为；不再调用独立 `teach-core`。

`strategyfinder` 内保存 research 正文，以及 prototype 正文、LOGIC 和 UI 副本，暂按原字节保留为可选资料，无强制运行依赖。

这些内部副本不增加公开入口，也无需另装官方 skill。官方原文保持不变，领域适配在外层完成。产物保存在用户工作区并由决策卡指向；提交临时分支、修改真实实现和 issue 操作仅在用户明确授权后执行。官方来源、固定提交与集中许可见 [UPSTREAM](../UPSTREAM.md)。

## 从旧版本迁移

`to-sop` 已改为 `to-plan`，工作区工件改为 `LEARNING-PLAN.md`。旧 SOP 只作为迁移输入，不自动删除或覆盖。`to-task` 取消无计划任务简报旁路。独立导航、十二周执行、单概念教学、独立复盘、通用知识库维护和协作画像入口退役；已有用户资料仍可按需读取。

退役 skill 的 `SKILL.md` 改为 `ARCHIVED.md`，保留支持资料与历史评测。安装器默认发现外层当前入口，不继续发现其内部参考；无需使用 `--full-depth`。归档入口不会被发现。
