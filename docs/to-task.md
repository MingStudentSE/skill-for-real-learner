## 它做什么

`to-task` 把当前学习 SOP 转换成一小批可适应的月、周、日或单次学习任务。每项任务都要产生练习或学习证据，并写清目标能力、行动、完成条件、反馈、投入、依赖和状态。

它规划眼前可执行的批次，而不是假装能预知整个学习旅程的精确顺序。

## 何时使用

你通过输入 `/to-task` 调用它；模型不会自行调用。

| 你的处境 | 该选什么 |
| --- | --- |
| 已有 `LEARNING-SOP.md`，需要安排当前一批行动 | `/to-task` |
| 方向已澄清，但尚未形成阶段方法或 `LEARNING-SOP.md` | [`to-sop`](to-sop.md) |
| 长期方向或精力取舍仍不清楚 | [`strategyfinder`](strategyfinder.md) |
| 学习使命或当前学习决策仍不清楚 | [`grill-with-learn`](grill-with-learn.md) |
| 需要跨会话的讲解、练习和课程工件 | [`teach-me`](teach-me.md) |
| 已积累行动结果，想检查学习设计是否有效 | [`study-review`](study-review.md) |

## 前提条件

需要当前 `MISSION.md` 与 `LEARNING-SOP.md`。已有 `TASKS.md`、学习记录和最近复盘能帮助它避免重复安排已经证明掌握的内容，并让新计划响应真实证据。

## 短闭环，而不是打勾清单

它的核心是**短闭环**：任务必须把具体情境中的尝试、可观察证据与来自他人、工具、标准或环境的反馈连起来。阅读、观看或完成课程可以是输入，但单独出现时不是能力证据。

远期只保留里程碑；越接近执行，任务越具体。新证据可以改变顺序、难度或后续范围，而不必把原计划当作承诺。

## 常见问题

**没有 SOP 可以直接生成任务吗？**

不适合。没有目标能力、方法和检查点，任务无法判断什么值得做；先用 [`to-sop`](to-sop.md) 建立依据。

**完成任务就表示能力已经形成吗？**

不一定。任务完成只说明行动发生；它需要留下解释、判断、迁移或真实反馈等证据，之后由 [`study-review`](study-review.md) 检查效果。

## 有效的信号

- 第一项无依赖任务可以马上开始。
- 每项任务都指向 SOP 中的一项目标能力，并有明确的证据与反馈来源。
- 当前批次在时间和精力上现实可行，后续内容没有被过度细化。

## 它在流程中的位置

它位于阶段方法和具体行动之间：读取 [`to-sop`](to-sop.md) 的产物，供 [`teach-me`](teach-me.md) 或学习者的真实行动读取。表现积累到检查点后，可手动调用 [`study-review`](study-review.md) 调整计划。
